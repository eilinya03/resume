Agent：AI从回答问题到执行任务

ChatGPT 是"嘴替"，Agent 是"能扛事的数字实习生"。

⏳ 等待学习
🎯 今日问题
Q. 你让 ChatGPT "帮我规划一次日本深度游"，它给你列了 10 个景点、5 家餐厅、3 条路线——写得很好，但你还是得自己去查机票、比价格、订酒店、查签证政策、把行程整理成文档发给同行伙伴。

为什么 AI 能"规划"但不能"执行"？如果 AI 能自己调用机票比价 API、分析签证政策、预订酒店、生成行程文档并发邮件——它还是同一个 ChatGPT 吗？
💡 线索卡片 · 我只给碎片，拼图你自己拼
Agent（智能体）= 大模型（脑子）+ 记忆模块（记住你说过的话）+ 规划引擎（拆解任务步骤）+ 工具库（能调用 API、查天气、发邮件）。ChatGPT 是"只动嘴"——它给你答案，但不帮你干活。Agent 是"既动脑子又动手"——它想好了怎么做，就真去做了。
来源：从思考，到行动：由Manus爆火谈AI Agent · 微信公众号
Agent 的核心是 ReAct 循环——不是"反应"，是"Reason（推理）+ Act（行动）"。流程是：用户提需求 → AI 思考"我要做什么"（Thought）→ AI 决定"调用什么工具"（Action）→ 工具返回结果（Observation）→ AI 再看结果思考"下一步做什么" → 循环直到完成。就像一个实习生接到任务，先想、再查、再汇报、再调整。
来源：拿下面试官：AI Agent工程师岗位通关实战指南 · 什么值得买
Agent 不是万能的。它适合"目标明确、步骤可拆解、工具可用"的任务——比如"监控竞品融资新闻，自动汇总发我邮箱"。它不适合"目标模糊、需要创意判断、结果不可预期"的任务——比如"帮我写一首让我女朋友感动的诗"。后者用 ChatGPT 更好，前者用 Agent 更好。
来源：入行AI产品经理必看：RAG、多模态、Agent学习顺序全解析 · CSDN
产品经理设计 Agent 产品时，核心不是"让 AI 更聪明"，是"定义清楚什么任务交给 Agent、什么任务留给人类、什么时候需要人类确认"。Agent 犯错比 ChatGPT 更危险——因为它真的会去订机票、真的会去发邮件、真的会去改数据库。每一个"行动"都需要产品设计兜底机制。

✅ 思考任务 · 完成后在微信回复"我学习好了"
  • 任务一：一句话解释 Agent（15分钟）
    用一句话向奶奶解释"什么是 AI Agent"——不能出现"ReAct""API""工具调用"这些词。
    检验标准：奶奶听完说"哦，就是雇了一个能自己查资料、自己办事的实习生呗"，你就成功了。
    💡 提示：想想你和实习生的区别——实习生不只是回答问题，他会自己查资料、写文档、发邮件、改表格，做完还向你汇报。Agent 就是数字版的实习生。
  • 任务二：判断用 ChatGPT 还是 Agent（15分钟）
    下面四个场景，哪些适合用 ChatGPT（聊天问答），哪些适合用 Agent（自动执行）？给出判断+理由。
    A. 用户说"帮我写一份项目周报"——ChatGPT 生成文字，用户复制粘贴到邮件里
    B. 用户说"每天早上 8 点，自动查公司竞品的新闻，汇总成简报发我邮箱"——需要定时执行、查新闻、写简报、发邮件
    C. 用户说"帮我分析一下这篇论文的创新点"——上传 PDF，AI 读完后给出分析
    D. 用户说"我下周三要去上海出差，帮我订机票、订酒店、查当地天气、生成行程表"——涉及多个工具调用
    💡 提示：判断标准是"任务是否需要多个步骤自动执行"+"是否需要调用外部工具（发邮件、订机票、查 API）"+"是否是一次性问答还是持续自动化"。
  • 任务三：设计 Agent 的"安全刹车"（20分钟）
    你设计了一个"数字实习生"Agent，它能自动帮销售团队发送跟进邮件。但有一天，它给 1000 个客户发送了错误的产品信息——因为知识库里的产品手册是旧版本。

    问题：作为产品经理，你会设计什么机制来防止这种"自动化灾难"？至少想出 3 个兜底措施。不是技术方案（比如"加个校验"），是产品设计层面的措施——比如"在什么环节让人类确认"。
    💡 提示：想想人类实习生犯错时，公司有什么流程？"重要邮件需要主管审批""发送前预览""每日限额""异常监控报警"——这些人类管理手段，怎么转化为 Agent 的产品设计？
👁️ 我的视角 · 这是我个人的看法，不是标准答案
🤔 我是这样想的...

我觉得 Agent 最大的陷阱是"过度自动化"。产品经理容易陷入一个思维："既然 Agent 能自动执行，那就让它自动做一切吧！"但这是个危险的想法。

人类实习生能自己发邮件，但重要邮件需要主管审批——不是因为实习生笨，是因为错误成本太高。Agent 也一样：它能自动做的事越多，它自动犯错的破坏力就越大。产品设计不是"让 Agent 做更多"，是"定义清楚什么必须人工确认"。

还有一个反直觉的点：Agent 的"自主性"和"可控性"是矛盾的。自主性越高，用户越省事儿；可控性越高，用户越放心。产品设计要在两者之间找平衡点——不是让 Agent 全自动化，也不是每一步都让用户确认，是"关键节点让人类看一眼"。

但也有人会反驳我："你说关键节点让人类确认，那 Agent 的价值不就是'省事儿'吗？如果每一步都要确认，用户为什么不自己做？Agent 和 Excel 宏有什么区别？"
